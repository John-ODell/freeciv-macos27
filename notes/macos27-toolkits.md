# macOS 26/27 changes that affect cross-platform GUI toolkits (Freeciv port notes)

Research date: 2026-10-15. Target: Freeciv 3.2.6+ (`refs/freeciv-S3_2`, `./fc_version` -> `3.2.6+`) on macOS 27.0.1 (Golden Gate), Apple Silicon, Xcode 27, Homebrew 7.0.9.
Everything below is web-sourced; each claim carries a URL. Items I could not confirm are marked **unverified** or **unknown**. Local file references (`client/...`, `meson.build`) are to the S3_2 tree in this repo and were checked with grep only (no builds).

Freeciv client facts used throughout (local grep):
- `meson_options.txt`: `clients` choices `gtk3.22, sdl2, qt, gtk4, stub, sdl3` (default `gtk4`); `audio` choices `none, sdl2, sdl3`; `qtver` default `qt6`; option `syslua`.
- gtk4 client installs a **native macOS menu bar**: `gtk_application_set_menubar(fc_app, G_MENU_MODEL(main_menubar))` at `client/gui-gtk-4.0/menu.c:4186`; it also runs a **nested GLib loop** for blocking dialogs (`g_main_loop_run(dlg_loop)` in `client/gui-gtk-4.0/gui_stuff.c:1149`, `blocking_dialog()`).
- gtk3.22 client has no `gtk_application_set_menubar`/`GtkosxApplication` use (grep empty), so its menu bar is an in-window GTK-drawn `GtkMenuBar`; it uses `gtk_dialog_run` nested loops in 9 files (`cityrep.c, dialogs.c, editgui.c, gui_main.c, repodlgs.c, plrdlg.c, theme_dlg.c, soundset_dlg.c, tileset_dlg.c`).
- sdl2 client: `SDL_CreateRenderer(main_data.screen, -1, flags)` (`client/gui-sdl2/graphics.c:588`), window created without `SDL_WINDOW_ALLOW_HIGHDPI` (grep empty), uses `SDL_WINDOW_FULLSCREEN_DESKTOP` (`gui_main.c:950,960`, `graphics.c:651`), consumes `SDL_TEXTINPUT` events (`gui_main.c:814`) but never calls `SDL_StartTextInput` (grep empty). SDL2_gfx: `dependency('SDL2_gfx', required: false)` with bundled fallback `dependencies/SDL2_gfx/SDL2_rotozoom.c` (`meson.build:3755-3760`). Audio: `dependency('SDL2_mixer')` (`meson.build:978`).
- Qt client: plain QtWidgets, `mr_menu : QMenuBar` (`client/gui-qt/menu.cpp:948`), `QMessageBox` dialogs, one `exec()` nested loop (`client/gui-qt/dialogs.cpp:4778`); no `QOpenGL`/`QRhi`/QML use (grep empty).
- Build deps: `icu_dep = dependency('icu-uc')` (`meson.build:686`); system Lua looked up as `lua-5.4`/`lua-54`/`lua54`/`lua5.4` (`meson.build:689`) with bundled `dependencies/lua-5.4` fallback.

## 1. Qt 6 (Homebrew `qt` 6.12.0) on macOS 26/27

**Versions / support**
- Homebrew `qt` is 6.12.0 with `arm64_golden_gate`, `arm64_tahoe`, `arm64_sequoia` bottles, not keg-only, no icu4c dependency. https://formulae.brew.sh/api/formula/qt.json
- Qt 6.12.0 released 2026-09-30. https://wiki.qt.io/Qt_6.12_Release
- Qt for macOS docs (6.12): target macOS 14.4 or higher "including macOS 26"; build env Xcode 16 (macOS 15 SDK) or higher; arm64/x86_64. macOS 27 not mentioned. https://doc.qt.io/qt-6/macos.html
- Qt's official stance: "Qt is generally forward-compatible on new operating system versions ... This includes macOS 26". https://www.qt.io/blog/qt-on-macos-26-tahoe
- Qt 6.12 Known Issues wiki: macOS section empty. https://wiki.qt.io/Qt_6.12_Known_Issues. Qt 6.11 Known Issues: macOS section empty. https://wiki.qt.io/Qt_6.11_Known_Issues. Qt 6.10 Known Issues: "Qt Widgets and Qt Quick macOS styles may exhibit drawing artefacts" under Liquid Glass; workaround build with Xcode 16 or set `UIDesignRequiresCompatibility=YES` in Info.plist. https://wiki.qt.io/Qt_6.10_Known_Issues (same text on 6.9/6.8 pages: https://wiki.qt.io/Qt_6.9_Known_Issues)

Source: Qt Jira search (REST API) https://qt-project.atlassian.net/rest/api/3/search/jql?jql=project%3DQTBUG%20AND%20(text~%22Tahoe%22%20OR%20text~%22macOS%2026%22%20OR%20text~%22macOS%2027%22%20OR%20text~%22Golden%20Gate%22)

- QTBUG-141541 "Tooltips at wrong position on macOS Tahoe" - still Reported, affects **6.12.0**. QTBUG-143784 "QTooltip displayed further off than below mouse cursor on macOS 26" - Reported. (Jira search URL above.)

**macOS 27-specific Qt bugs (from Jira, 2026-10-15)**
- QTBUG-150017 "[macOS 27] Item-view check-state indicators are invisible with macos style" - affects 6.11.2, **6.12.0 RC**; Fixed in 6.8.10, **6.12.1**, 6.13.0 (commits 774ebf546bec dev, 39c36a08 on 6.12). QTreeView/QTableWidget/Qt Creator settings affected; Fusion style shows them. https://qt-project.atlassian.net/rest/api/3/issue/QTBUG-150017 (dups QTBUG-151332, QTBUG-151281). **Freeciv Qt client is in scope**: any checkable item-view (e.g. options/city dialogs) will show no checkbox glyph with the default style on 6.12.0.

- QTBUG-151608 "Native QFontDialog::getFont no longer usable on macOS 27" (opened 2026-10-15, 27.2 beta; NSFontPanel internals changed). https://qt-project.atlassian.net/rest/api/3/issue/QTBUG-151608. Not used by Freeciv.

- Other open macOS 27 items: QTBUG-151331 (QNetworkInterface MAC placeholder), QTBUG-151157 (multimedia subtitles), QTBUG-150276 (qtwebengine build). https://qt-project.atlassian.net/rest/api/3/search/jql?jql=project%3DQTBUG%20AND%20(text~%22macOS%2027%22%20OR%20text~%22Golden%20Gate%22)%20AND%20statusCategory%20!%3D%20Done
- **No QTBUG found describing a hang/freeze when a QDialog is opened from a native menu action on macOS 27** (searched "macOS 27", "Golden Gate", "Tahoe"). Qt's menu dispatch is **queued**, see section 4.

**HiDPI / Metal / QRhi / window tabs**
- Nothing Tahoe/27-specific found for HiDPI or Metal in Jira for QtWidgets. QTBUG-149985 (OpenGL offscreen/swapchain crash, fixed 6.12.1) and QTBUG-147228 (TSan on QMetalLayer displayLock, fixed 6.12.0) are QRhi-side and irrelevant to a raster QPainter client. https://code.qt.io/cgit/qt/qtreleasenotes.git/about/qt/6.12.0/release-note.md
- macOS window tabs: **unknown** - no Tahoe/27 Qt report found.
- Qt 6.12.0 release-note items that matter for packaging: "Apple builds are relocatable by default" (c596e7af244); `QLibraryInfo` paths for bundled apps follow bundle conventions so most apps don't need `qt.conf` (002acd47bb3); `macdeployqt` no longer writes `qt.conf` (91c39b355d7); `QScreen::grabWindow` now uses ScreenCaptureKit and triggers a permission dialog (6c12b7323db); unified title/toolbar no longer uses textured NSWindow (cb18a8e32ca). https://code.qt.io/cgit/qt/qtreleasenotes.git/about/qt/6.12.0/release-note.md
- AGL framework was removed from the macOS 26 SDK; Qt < 6.8.4 / 6.9.2 fails to link ("ld: framework 'AGL' not found", QTBUG-137687). Not an issue for 6.12. https://forum.qt.io/topic/163262/ld-framework-agl-not-found-on-macos-tahoe
- Qt docs note that `QMenu` objects in the native bar "don't receive events through normal handlers" - use `aboutToShow/aboutToHide`; `DYLD_LIBRARY_PATH` overrides `@executable_path` install names. https://doc.qt.io/qt-6/macos-issues.html

**Is Freeciv's Qt client in the affected area?** Yes for QTBUG-150017 (invisible check indicators, 6.12.0), QTBUG-141541 (tooltip placement), QTBUG-149290 (dark-mode line-edit borders) and QTBUG-151046 (menu icons). No for Metal/QRhi/QML items. Fix release for the first three is **6.12.1** (not yet in Homebrew as of 2026-10-15).

**Renderers / OpenGL on GTK4 macOS**
- `GSK_RENDERER` accepted values in 4.24.1 docs: `help, broadway, cairo, opengl, gl:, vulkan`; `GSK_DEBUG` (`renderer, shaders, fallback, ... full-redraw, cairo`); `GDK_DEBUG` includes `eventloop` ("mostly macOS") and `opengl`; `GDK_BACKEND=macos`; `GDK_DISABLE=gl,vulkan,...`. https://docs.gtk.org/gtk4/running.html

**Menu bar integration**
- GTK3: `gtk-mac-integration` (`GtkosxApplication`) is a separate library; Freeciv does not use it. ## 3. SDL2 / sdl2-compat / SDL3 on macOS 26/27

**Homebrew switch**
- `sdl2` formula was replaced by `sdl2-compat` in homebrew-core PR #285604 "sdl2: replace with `sdl2-compat`" (opened 2026-06-01, **merged 2026-06-19**); new formula PR #281814 (merged 2026-06-01). https://api.github.com/search/issues?q=repo:Homebrew/homebrew-core+sdl2-compat+sdl2+in:title+is:pr
- `sdl2-compat` 2.32.74, alias `sdl2`, runtime dep `sdl3` (no-linkage: dlopen), bottles `arm64_golden_gate/tahoe/sequoia`, not keg-only, no caveats. https://formulae.brew.sh/api/formula/sdl2-compat.json
- `sdl3` is 3.4.18 in Homebrew. https://formulae.brew.sh/formula/sdl3
- `sdl2_image` 2.8.12_1, `sdl2_ttf` 2.24.0, `sdl2_mixer` 2.8.2, `sdl2_gfx` 1.0.4_1 all now depend on `sdl2-compat` and have `arm64_golden_gate` bottles. https://formulae.brew.sh/api/formula/sdl2_image.json , https://formulae.brew.sh/api/formula/sdl2_ttf.json , https://formulae.brew.sh/api/formula/sdl2_mixer.json , https://formulae.brew.sh/formula/sdl2_gfx (sdl2_gfx got a Linux `-lm` fix for compat: https://github.com/Homebrew/homebrew-core/pull/285747)
- Bundling consequence: sdl2-compat dlopens `libSDL3`, so `fixup_bundle`/`macdeployqt`-style bundlers miss it and the app aborts with "Failed loading SDL3 library"; copy `libSDL3.0.dylib` into the bundle. https://github.com/HarbourMasters/Ghostship/pull/233 , https://github.com/libsdl-org/sdl2-compat/issues/611 , https://github.com/andiyar/OniARM64/issues/118
- `SDL2COMPAT_DEBUG_LOGGING=1` prints compat debug to stderr; `SDL2COMPAT_ALLOW_SYSWM` controls SysWM events; must be set before process start. https://raw.githubusercontent.com/libsdl-org/sdl2-compat/main/README.md
- sdl2-compat releases 2.32.74 (02 Oct), 2.32.72 (02 Sep), 2.32.70 (08 Jun); 2.32.68 added an `SDL3_VERSION` hint. No macOS-specific release-note lines. https://github.com/libsdl-org/sdl2-compat/releases

**Behavioural differences that matter for a 2D software-rendered client (SDL3 semantics underneath)** https://raw.githubusercontent.com/libsdl-org/SDL/main/docs/README-migration.md
- "high DPI support is always enabled" in SDL3 (the SDL2 hint is gone); window size is in window coordinates, `SDL_GetWindowSizeInPixels()`/`SDL_GetRenderOutputSize()` give pixels; a window gets a high-density backbuffer only with `SDL_WINDOW_HIGH_PIXEL_DENSITY`; "On macOS, you must enable the NSHighResolutionCapable property in Info.plist" for a high-DPI GL canvas. https://wiki.libsdl.org/SDL3/SDL_CreateWindow. sdl2-compat implements `SDL_HINT_VIDEO_HIGHDPI_DISABLED` and `SDL_HINT_MOUSE_RELATIVE_SCALING` since PR #350 (Feb 2025) - mapping details not shown in the PR page (**unverified**). https://github.com/libsdl-org/sdl2-compat/pull/350. Freeciv's sdl2 client never passes `SDL_WINDOW_ALLOW_HIGHDPI`, so it should get a 1x backing store (points == pixels, blurry-but-consistent on Retina) - **expected, unverified on 27**. Related compat reports: #427 (`SDL_GetWindowSizeInPixels` == `SDL_GetWindowSize` at fractional scale, Wayland), #269 (ALLOW_HIGHDPI ignored on Wayland). https://github.com/libsdl-org/sdl2-compat/issues/427 , https://github.com/libsdl-org/sdl2-compat/issues/269
- Mouse: SDL3 "Mouse events use floating point values", "no longer automatically scaled by the SDL renderer"; sdl2-compat is responsible for re-applying SDL2 logical-size scaling (Wesnoth saw squished fullscreen + misaligned clicks, #279, closed). https://github.com/libsdl-org/sdl2-compat/issues/279
- Renderer: SDL3 "textures now default to linear filtering"; logical presentation is separate from viewport; batching always on. (migration doc). Whether sdl2-compat maps `SDL_HINT_RENDER_SCALE_QUALITY` to per-texture scale mode: **unverified**.
- Text input: SDL3 "Text input is no longer automatically enabled when initializing video" and is per-window; sdl2-compat restores SDL2's always-on text input (commit 2a9b84e0c, in 2.32.50) but **does not** force `ApplePressAndHoldEnabled` off, so on macOS 26 a held key opens the accent popup and key repeat stops (issue #620, open; only SDL3 >= 3.4.0 honours `SDL_HINT_MAC_PRESS_AND_HOLD`). Workarounds: env `SDL_MAC_PRESS_AND_HOLD=0`, or call `SDL_StopTextInput()` at startup and start/stop on demand. https://github.com/libsdl-org/sdl2-compat/issues/620 , https://github.com/libsdl-org/SDL/releases/tag/release-3.4.0. **Freeciv sdl2 client relies on always-on text input (`SDL_TEXTINPUT` without `SDL_StartTextInput`)** - fine under sdl2-compat, but held movement keys will hit #620.
- Fullscreen: `SDL_WINDOW_FULLSCREEN_DESKTOP` is an "unofficial" flag under compat; a window frame may be briefly visible (#474, closed). https://github.com/libsdl-org/sdl2-compat/issues/474
- Window ops: sdl2-compat forces `SDL_VIDEO_SYNC_WINDOW_OPERATIONS` to emulate SDL2's synchronous resizes; `SDL_SetWindowSize` -> `Cocoa_SyncWindow` pumps Cocoa events re-entrantly and an FNA game segfaults in `Cocoa_HandleMouseEvent` (sdl2-compat #616 / SDL #16105, both open, maintainer suspects memory corruption). https://github.com/libsdl-org/sdl2-compat/issues/616 , https://github.com/libsdl-org/SDL/issues/16105
- SDL3 3.4.16 (02 Sep): "Fixed windows staying on screen after SDL_Quit() on macOS". 3.4.18 (02 Oct): "Fixed the Steam Controller showing up twice on macOS 27". No other macOS 26/27 entries. https://github.com/libsdl-org/SDL/releases/tag/release-3.4.16 , https://github.com/libsdl-org/SDL/releases/tag/release-3.4.18

## 4. The Tk menu-freeze class and whether GTK / SDL / Qt share the mechanism

**The Tk/IDLE/Thonny bug (confirmed, macOS 27 only)**
- CPython #158053 "IDLE on macOS 27 hangs when a menu command opens a dialog" (2026-09-24): beach ball on IDLE > Settings / Save As / Run Module; macOS 27.0 (26A428) and 27.0.1; Python 3.13.14+Tk 8.6.18 and 3.14.7+Tk 9.0.4; not on Tahoe 26.6.2; main thread "stuck inside the macOS menu-bar callback" (MenuBarClientCore -> Tk -> nested loop -> select). Duplicate #158587. Apple Feedback FB24915676. https://github.com/python/cpython/issues/158053
- Thonny #3934 (Settings/About/Manage packages freeze on 27.0, Thonny 4.1.7/5.0.0, Tk 8.6.17 and 9.0.4) and PR #3937 "Defer modal dialogs opened from menu callbacks on macOS 27" (open, milestone 5.0.1); plug-in workaround `after(1, ...)`. https://github.com/thonny/thonny/issues/3934 , https://github.com/thonny/thonny/pull/3937 , https://github.com/gorizilla/thonny-macos27-menufix
- Tk ticket 33b3af1cea "macOS 27 beta: modal dialog opened synchronously from a menu command becomes unresponsive" (filed 2026-07-21 on 27.0 beta 3/4; Tk 8.6.17 and 9; closed Fixed 2026-10-05, reopened 2026-10-11 over a `Tcl_Preserve` lifetime issue, open as of 2026-10-13). https://core.tcl-lang.org/tk/tktview/33b3af1ceac681ad0f77
- **Mechanism (Marc Culler, Tk maintainer):** Tk never calls `CFRunLoopRun`; it pulls events from Apple's queue in its Tcl event source. `TkMacOSXEventsSetupProc`/`CheckProc` only run when `[[NSRunLoop currentRunLoop] currentMode]` is **nil** ("runloopMode will be nil if we are in a Tcl event loop"). https://raw.githubusercontent.com/tcltk/tk/main/macosx/tkMacOSXNotify.c. On macOS 26 the mode is nil before/after the `NSEventTrackingRunLoopMode` run that handles menu tracking; on macOS 27 it is `NSDefaultRunLoopMode` - "Apple wraps the menu run loop in a generic default run loop" that does not end until the menu action returns. A menu action that waits for user input (modal dialog / nested loop) never returns, so Tk never pumps again. Run-loop nesting in `TclpWaitForEvent` peaked at 2 on 26 and 3 on 27. The menu bar appears to have moved into a private framework, `MenuBarClientCore`. (ticket above; also CPython thread.)
- **Fix:** Tk now dispatches `tkMenuItemInvoke:` via `Tcl_DoWhenIdle(invokeMenuIdleTask, args)` with `Tcl_Preserve` on the menu and interp, so the AppKit action returns immediately. Merged to `core-8-6-branch`, `core-9-0-branch`, `main` on 2026-10-05. https://raw.githubusercontent.com/tcltk/tk/main/macosx/tkMacOSXMenu.c. Not in any shipped release: Tk 9.0.4 (Jun 2026) and 8.6.18 (May 2026) are the latest; tcl-lang lists 9.1.0 (Sep 29, 2026) which predates the fix; python.org installers are being held until an official Tk release. https://www.tcl-lang.org/software/tcltk/9.1.html , https://www.tcl-lang.org/software/tcltk/download.html , https://github.com/python/cpython/issues/158053. Homebrew `tcl-tk` is 9.1.0. https://formulae.brew.sh/api/formula/tcl-tk.json
- Apple side: no AppKit release-note item mentions menu tracking or run-loop modes; the only documented NSMenu changes are image visibility (`preferredImageVisibility`), "Some NSMenu APIs, such as highlightedItem, will not work in context menus" (178288949), and a `NSTextView` context-menu rearrangement. https://developer.apple.com/tutorials/data/documentation/macos-release-notes/macos-27-release-notes.json. Culler expects Apple to answer "won't fix" because Tk's use of the AppKit loop is unorthodox.

**Does the same mechanism hit the other toolkits? (run-loop API each uses, from source)**

| Toolkit | How it pumps Cocoa | Run-loop modes it registers | Native menu action -> app callback | Exposure to the macOS 27 change |
|---|---|---|---|---|
| Tk (Aqua) | Own Tcl notifier; pulls events via Tcl event source, gated on `currentMode == nil`; adds `NSEventTrackingRunLoopMode` to the notifier | nil / tracking | `tkMenuItemInvoke:` was synchronous; now `Tcl_DoWhenIdle` | **Confirmed broken on 27 (fixed in Tk source, unreleased)** |
| GTK3 quartz (`gdk/quartz/gdkeventloop-quartz.c`) | Replaces GLib poll func; `[NSApp nextEventMatchingMask:... inMode:NSDefaultRunLoopMode]`; no `[NSApp run]`; when CFRunLoop is in control (modal/drag) a `CFRunLoopObserver` on `kCFRunLoopCommonModes` drives GLib prepare/check/dispatch; `getting_events`/`current_loop_level` guards | `NSDefaultRunLoopMode`, `kCFRunLoopCommonModes`; never checks `currentMode`, never references `NSEventTrackingRunLoopMode`/`NSModalPanelRunLoopMode` | In-window GtkMenuBar: no native action at all. `GtkApplication` menubar: `didSelectItem:` synchronous | Freeciv gtk3.22 client has **no native menu**, so the Tk trigger (AppKit menu callback that nests) cannot occur. `gtk_dialog_run` nests only inside GLib's own loop. **No report of a GTK3 freeze on 27 found.** https://gitlab.gnome.org/GNOME/gtk/-/raw/gtk-3-24/gdk/quartz/gdkeventloop-quartz.c |

Because GTK's observer is on common modes it should keep dispatching GLib from inside that loop (unlike Tk, which stops pulling events), but **no evidence either way on 27: unknown**. Only known 27 report is #8435 (shortcut glyphs). https://gitlab.gnome.org/GNOME/gtk/-/raw/main/gdk/macos/gdkmacoseventsource.c |
| SDL3 (`src/video/cocoa/SDL_cocoaevents.m`) | `Cocoa_PumpEventsUntilDate`: `[NSApp nextEventMatchingMask:NSEventMaskAny untilDate:... inMode:NSDefaultRunLoopMode dequeue:YES]`; `SDL3Application sendEvent:` override; `runModalSession:` only for SDL modal sessions; no `[NSApp run]`, no CFRunLoop, no mode checks, no 26/27 availability checks | `NSDefaultRunLoopMode` only | Default menus point at AppKit selectors (`hide:`, `terminate:` -> `SDL_SendQuit()` which just queues an event); no app callback runs inside menu tracking | **Not exposed**: nothing of the app's runs inside the AppKit menu callback. While a menu is open SDL's loop is simply blocked (always true). https://raw.githubusercontent.com/libsdl-org/SDL/main/src/video/cocoa/SDL_cocoaevents.m |
| Qt 6 (`qcocoaeventdispatcher.mm`, `qcocoaapplicationdelegate.mm`) | `[NSApp run]` when Qt owns the loop (`nsAppRunCalledByQt`), else `nextEventMatchingMask ... NSDefaultRunLoopMode`; timers/posted-events sources and a waiting observer on `kCFRunLoopCommonModes`; `CFRunLoopAddCommonMode(NSModalPanelRunLoopMode)`; dialogs via `[NSApp runModalSession:]`; `interrupt()`/`[NSApp stop:]` for nested exec | default, modal panel, common modes; no `currentMode` gating | `-[QCocoaApplicationDelegate qt_itemFired:]` emits `QCocoaMenuItem::activated` with **`Qt::QueuedConnection`** - the QAction fires on the next Qt event-loop turn, after the AppKit action has returned | **Already deferred - the exact shape of the Tk fix.** A `QDialog::exec()` from a menu action therefore runs outside the AppKit callback. No macOS 27 hang report in Jira. https://code.qt.io/cgit/qt/qtbase.git/plain/src/plugins/platforms/cocoa/qcocoaeventdispatcher.mm , https://code.qt.io/cgit/qt/qtbase.git/plain/src/plugins/platforms/cocoa/qcocoaapplicationdelegate.mm |

Related evidence that macOS 27 changed menu-dispatch context: QTBUG-147449 (`NSApp.currentEvent` is an AppKit-defined event during menu activation on 27). https://qt-project.atlassian.net/rest/api/3/issue/QTBUG-147449. A general reminder that `kCFRunLoopCommonModes` includes `NSEventTrackingRunLoopMode` (so observers/timers registered there run during menu tracking): https://github.com/tauri-apps/tao/issues/1324

## 6. Lua, readline/libedit, icu4c@78, gettext, pkg-config on macOS 27 Homebrew

- `lua` is **5.5.1** (alias `lua@5.5`), no deps, not keg-only. `lua@5.4` is 5.4.9, **keg-only (versioned)**, **deprecated 2026-08-26 ("unsupported"), disabled 2027-08-26**. https://formulae.brew.sh/api/formula/lua.json , https://formulae.brew.sh/api/formula/lua@5.4.json. Freeciv's meson looks for `lua-5.4`/`lua-54`/`lua54`/`lua5.4` pkg-config names (`meson.build:689`) and otherwise builds the bundled Lua 5.4 - so `-Dsyslua=true` needs `PKG_CONFIG_PATH=$(brew --prefix lua@5.4)/lib/pkgconfig`; the default (`lua` 5.5) will not satisfy it. Whether Homebrew's lua@5.4 ships a `.pc` file: **unverified** (an older Linuxbrew formula said "We ship our own pkg-config file as Lua no longer provide them upstream", https://raw.githubusercontent.com/Homebrew/linuxbrew-core/master/Formula/lua.rb).
- `readline` 8.3.6 is **keg-only (`:shadowed_by_macos`: "macOS provides BSD libedit")**. https://formulae.brew.sh/api/formula/readline.json. Builds that want GNU readline must set `PKG_CONFIG_PATH`/`LDFLAGS`/`CPPFLAGS` to its prefix; otherwise the system libedit is what `-lreadline` style probes may or may not find.
- `icu4c@78` 78.3 is **keg-only (`:shadowed_by_macos`: "macOS provides libicucore.dylib (but nothing else)")**. https://formulae.brew.sh/api/formula/icu4c@78.json. Freeciv requires `icu-uc` via pkg-config (`meson.build:686`) -> set `PKG_CONFIG_PATH="$(brew --prefix icu4c@78)/lib/pkgconfig"` or meson reports "Dependency icu-uc not found".
- `gettext` is **not keg-only** (version 1.0; deps json-c, libunistring). https://formulae.brew.sh/api/formula/gettext.json. `libintl` headers are therefore under the normal prefix.
- `pkg-config` was replaced by `pkgconf` 3.0.8 (aliases `pkg-config`, `pkgconfig`); Homebrew's pkg-config deliberately ignores undeclared/keg-only kegs. https://formulae.brew.sh/api/formula/pkgconf.json , https://github.com/orgs/Homebrew/discussions/5991 , https://github.com/Homebrew/homebrew-core/issues/198881
- Homebrew's own guidance for building outside brew: `PKG_CONFIG_PATH="$(brew --prefix X)/lib/pkgconfig"`, `CPPFLAGS=-I.../include`, `LDFLAGS=-L.../lib`; "Some formulae use lib/pkgconfig, some use share/pkgconfig and some provide no pkg-config metadata." https://docs.brew.sh/How-to-Build-Software-Outside-Homebrew-with-Homebrew-keg-only-Dependencies , https://docs.brew.sh/FAQ
- `meson` 1.12.1 (bottle `all`). https://formulae.brew.sh/api/formula/meson.json
- Xcode 27 dropped ld64/`-ld_classic` (see 5) - remove any `-Wl,-ld_classic` from `LDFLAGS`/meson cross files.

## 7. Checklist: symptoms to watch for when launching each Freeciv client on macOS 27, and the diagnostic for each

General (any client)
- **Beach ball after choosing a menu item** -> while frozen: `sample <pid> 5 -file /tmp/s.txt` or `spindump <pid> 5 -file /tmp/sd.txt`; look for `MenuBarClientCore`, `-[NSMenu ...]`, `-[NSApplication run]` / `CFRunLoopRunSpecific` with a nested GLib/Tcl/Qt loop above it. In lldb: `po [[NSRunLoop currentRunLoop] currentMode]` (Tk's diagnosis: `NSDefaultRunLoopMode` on 27 vs nil on 26). Compare with the keyboard shortcut for the same action (shortcuts do not go through the menu callback: https://github.com/gorizilla/thonny-macos27-menufix).
- **App "Not Opened"/Gatekeeper** -> `spctl --assess --type execute -vv Foo.app`, `codesign -dvvv --entitlements - Foo.app`, `xattr -l Foo.app`; use Privacy & Security > Open Anyway (https://support.apple.com/en-us/102445).
- **dyld: Library not loaded** -> `otool -L` on the binary, `DYLD_PRINT_LIBRARIES=1 ./freeciv-xxx`; remember hardened runtime strips `DYLD_*` (https://bugs.python.org/issue40198); for sdl2-compat check `libSDL3.0.dylib` is reachable (https://github.com/libsdl-org/sdl2-compat/issues/611).
- **meson "Dependency X not found"** -> `pkg-config --debug --libs icu-uc` with `PKG_CONFIG_PATH` set for `icu4c@78`, `lua@5.4`, `readline` (keg-only); `brew doctor --json`; `brew fetch --force --force-bottle <f>` for stale 27 bottle manifests (https://github.com/Homebrew/brew/issues/23930).
- Link errors mentioning `ld_classic` -> drop the flag (Xcode 27 removed ld64).

gtk4 client (`freeciv-gtk4`)
- Menu bar shows `N`/`Q` instead of `⌘N`/`⌘Q` -> expected on 27 (GTK #8435); cosmetic.

If confirmed, the fix shape is to defer the action with `g_idle_add` (what gtk-mac-integration and Tk do). Status on 27: **unknown**.

- Crash on drag-and-drop -> fixed in 4.21.4 (!9311 "macOS 26"); 4.24.1 has it.

- **Blurry rendering in HiDPI** and **cannot drag column separators / GtkScale sliders** -> expected with Homebrew 3.24.52_1 on 26.5+/27 (#8233/#8234, fix d75c8720 unreleased). - Dialog renders black after an external frame change (#8254, macOS 26.2) -> force a redraw/resize.
- Menu freeze class: not applicable (no native menu); if a freeze occurs it is a different bug - sample it.

sdl2 client (`freeciv-sdl2`, now sdl2-compat over SDL3 3.4.18)

Qt client (`freeciv-qt`, Qt 6.12.0)

- Menu icons missing -> QTBUG-151046 (cosmetic).
- Tooltips mispositioned -> QTBUG-141541/143784.
